# 5 天 Design Sprint 排期

> 来源 Skill：`design-sprint`  
> 范围：v0.2.0 设计阶段

| 日期 | 重点活动 | 产出物 | 参与角色 |
|---|---|---|---|
| Day 1 | 理解：复盘 PRD，对齐目标 | `clarify.md` 二次确认、问题树 | PM / UI / 前后端 |
| Day 2 | 发散：接口草案 + UI 草图 | 接口列表草稿、Pencil DSL 草图 | 前后端 / UI |
| Day 3 | 决策：关键技术选型对比 | `decision-001.md` 等决策记录 | 全员 |
| Day 4 | 原型：把草图变 `.pen` 文件 | `*.pen` 设计稿、UI 规范扫描报告 | UI / 前端 |
| Day 5 | 评审：多角色逐接口讨论 | `design-review.md` 多角色纪要 | 全员 |

## 输出约束

- 所有接口草案必须在 Day 5 评审前完成 OpenAPI YAML 草稿
- 所有 UI 稿必须通过 `design-ui-check` 颜色 / 字体 / 间距 / 圆角扫描
- 所有决策记录必须有 ≥ 2 个候选选项 + 采纳原因
