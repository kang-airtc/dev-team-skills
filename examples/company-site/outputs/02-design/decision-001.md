# DEC-001：评论是否需要审核流程

> 来源 Skill：`design-discuss`  
> 决策时间：2026-04-12  
> 关联变更：RC-001

## 背景

公开站允许匿名访客发评论。是否在写入后立即对所有人可见，存在不同意见。

## 选项对比

| 选项 | 优点 | 缺点 |
|---|---|---|
| A 直接显示 | 实时性好、运营成本低 | 垃圾评论无防线 |
| B 先审后显 | 内容可控 | 实时性差、需后台值班 |
| C 自动过滤 + 人工抽检 | 平衡 | 实现复杂度高 |

## 采纳

**B（先审后显）**

## 原因

教学场景下后台 UI 价值更大，让 admin 在 `/dashboard/comments` 能"显示/隐藏"评论。同时本项目无外部用户增长压力，先审后显的延迟成本可接受。

## 落地

- `comments.is_visible` 默认 `false`
- 公开站列表默认过滤 `is_visible=true`
- 后台 `/dashboard/comments` 提供逐条"显示/隐藏"开关
- 文案：访客提交后提示"评论已提交，审核后显示"

## 复盘条件

如评论量 > 50 条/天或 admin 审核响应延迟 > 4 小时，复评 C 选项。
