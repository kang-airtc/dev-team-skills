# Incident Report - 故障复盘报告

基于故障信息生成结构化的复盘报告（Postmortem），包含时间线、根因分析、改进措施。

## 触发场景

- 故障解决后复盘
- 生成故障报告归档
- 团队学习改进
- 向领导汇报故障

## 目录结构

```
incident-report/
├── SKILL.md
├── scripts/
│   └── generate.py
└── assets/
    └── postmortem-template.md
```

## 依赖

- Python 标准库

## 使用方法

```bash
# 交互式生成
python3 .opencode/skills/incident-report/scripts/generate.py

# 命令行参数
python3 .opencode/skills/incident-report/scripts/generate.py \
  --title "数据库连接池耗尽" \
  --severity P1 \
  --duration 30 \
  --output postmortem-20240115.md
```

参数：
- `--title, -t`：故障标题
- `--severity`：严重级别（P0/P1/P2/P3）
- `--duration`：持续时间（分钟）
- `--output, -o`：输出路径

## 报告结构

```markdown
# 故障复盘报告：数据库连接池耗尽

**故障编号**: INC-20240115-001
**严重级别**: P1
**持续时间**: 30 分钟
**影响范围**: 用户无法登录和下单

## 时间线

| 时间 | 事件 |
|------|------|
| 14:20 | 监控告警：数据库连接数达 90% |
| 14:25 | 用户反馈无法登录 |
| 14:30 | 确认数据库连接池耗尽 |
| 14:35 | 重启应用释放连接 |
| 14:50 | 服务恢复正常 |

## 根因分析

**直接原因**: 数据库连接池配置过小（max_connections=20）

**深层原因**:
1. 连接未正确释放（代码中缺少 close）
2. 缺少连接超时设置
3. 监控告警阈值设置过高（90%）

## 影响评估

- **影响用户数**: 约 500 人
- **业务影响**: 登录、下单功能不可用
- **数据影响**: 无数据丢失

## 改进措施

| 措施 | 负责人 | 截止时间 | 状态 |
|------|--------|---------|------|
| 增加连接池大小至 100 | 后端开发 | 2024-01-17 | 待办 |
| 添加连接超时和释放 | 后端开发 | 2024-01-17 | 待办 |
| 调整告警阈值至 70% | 运维 | 2024-01-16 | 待办 |
| 添加连接池监控面板 | 运维 | 2024-01-20 | 待办 |

## 经验教训

1. 连接池大小需要根据并发量合理配置
2. 代码中必须确保连接释放
3. 告警阈值应留足够缓冲时间
```

## 边界

- 只生成报告模板，需要人工填充具体内容
- 不自动收集故障信息
- 严重级别需要人工判断
