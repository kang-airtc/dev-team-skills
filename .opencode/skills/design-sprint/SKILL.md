# Design Sprint - 设计冲刺

提供 Google Design Sprint 方法论的结构化流程，帮助团队在5天内完成从问题定义到原型验证的设计过程。

## 触发场景

- 需要快速验证产品概念
- 新产品功能从0到1的设计
- 解决复杂设计问题，需要团队集中攻坚
- 现有方案遇到瓶颈，需要重新思考

## 依赖

仅使用 Python 标准库，无需额外依赖。

## 使用方法

```bash
# 生成为期5天的冲刺计划
python3 .opencode/skills/design-sprint/scripts/sprint.py \
  --topic "重新设计用户注册流程" \
  --output "sprint-plan.md"

# 查看第3天任务
python3 .opencode/skills/design-sprint/scripts/sprint.py \
  --topic "优化结算页面" \
  --day 3 \
  --output "day3-tasks.md"
```

参数：
- `--topic, -t`：冲刺主题/目标
- `--day, -d`：可选，只输出指定天的任务（1-5）
- `--output, -o`：输出路径，默认 `sprint-plan.md`

## 5天冲刺流程

| 天数 | 主题 | 核心任务 | 产出物 |
|------|------|----------|--------|
| **Day 1** 理解 | 明确问题 | 用户调研、竞品分析、利益相关者访谈 | 问题定义文档 |
| **Day 2** 发散 | 探索方案 | 头脑风暴、疯狂8分钟、方案草图 | 概念草图集 |
| **Day 3** 决策 | 确定方向 | 方案评审、投票、故事板 | 选定方案+故事板 |
| **Day 4** 原型 | 快速实现 | 制作高保真原型、准备测试脚本 | 可点击原型 |
| **Day 5** 验证 | 用户测试 | 5人用户测试、记录反馈、总结洞察 | 测试报告 |

## 输出格式

```markdown
# 设计冲刺计划：{主题}

## Day 1: 理解（Understand）

**目标**: 深入理解用户问题

### 上午任务
- [ ] 09:00-09:30 开场介绍（15分钟）
- [ ] 09:30-10:30 利益相关者访谈
- [ ] 10:30-12:00 用户调研回顾

### 下午任务
- [ ] 14:00-15:30 竞品分析
- [ ] 15:30-16:30 问题定义工作坊
- [ ] 16:30-17:00 总结并确定设计原则

**产出物**: 
- 用户画像（1-2个）
- 问题定义陈述
- 设计原则清单

---

## Day 2: 发散（Sketch）
...
```

## 边界

- 本Skill提供的是**流程模板**，实际执行需要团队配合
- 每天的时间安排可根据团队实际情况调整
- 用户测试环节需要真实用户参与，无法自动化
- 建议团队规模：5-7人（含设计师、产品经理、开发）
