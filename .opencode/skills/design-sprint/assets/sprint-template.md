## Day 1: 理解（Understand）

**核心目标**: 深入理解用户问题，建立共识

### 上午（3小时）

- [ ] **09:00-09:30 开场介绍**
  - 介绍冲刺流程和规则
  - 明确冲刺目标
  - 介绍参与角色

- [ ] **09:30-10:30 利益相关者访谈**
  - 了解业务背景
  - 明确成功标准
  - 收集已有数据和假设

- [ ] **10:30-12:00 用户调研回顾**
  - 回顾现有用户研究
  - 更新用户画像
  - 识别关键用户痛点

### 下午（3小时）

- [ ] **14:00-15:30 竞品分析**
  - 分析3-5个竞品方案
  - 记录亮点和不足
  - 提取可借鉴的模式

- [ ] **15:30-16:30 问题定义工作坊**
  - "我们该如何..."（How Might We）问题收集
  - 问题分类和优先级排序
  - 确定冲刺要解决的焦点问题

- [ ] **16:30-17:00 总结**
  - 确定设计原则（3-5条）
  - 明确约束条件
  - 回顾第一天成果

**产出物清单**:
- [ ] 用户画像（1-2个）
- [ ] HMW 问题清单（按优先级排序）
- [ ] 设计原则

---

## Day 2: 发散（Sketch）

**核心目标**: 尽可能多地产生创意方案

### 上午（3小时）

- [ ] **09:00-09:30 灵感参考**
  - 展示收集的优秀案例
  - 讨论启发点

- [ ] **09:30-10:30 闪电演讲**
  - 每人3分钟分享想法
  - 不批评，只记录

- [ ] **10:30-12:00 疯狂8分钟**
  - 8个格子，每个1分钟画一个方案变体
  - 强制快速产出，不纠结细节

### 下午（3小时）

- [ ] **14:00-15:30 方案草图**
  - 每个人独立完成3屏方案草图
  - 包含：标题、关键界面、说明文字
  - 匿名提交

- [ ] **15:30-16:30 方案展示**
  - 每人3分钟介绍自己的方案
  - 其他人记录问题和亮点

- [ ] **16:30-17:00 收集反馈**
  - 贴便签记录想法
  - 整理所有方案

**产出物清单**:
- [ ] 概念草图（每人至少1套）
- [ ] 方案展示记录

---

## Day 3: 决策（Decide）

**核心目标**: 选定最佳方案，制作故事板

### 上午（3小时）

- [ ] **09:00-09:30 方案回顾**
  - 把所有方案贴在墙上
  - 快速浏览所有方案

- [ ] **09:30-10:30 静默投票**
  - 每人有3票，贴在最认可的方案上
  - 不能投自己的方案

- [ ] **10:30-12:00 方案讨论**
  - 讨论票数最高的方案
  - 识别冲突和折中点
  - 决定最终方向（可以是组合方案）

### 下午（3小时）

- [ ] **14:00-15:30 制作故事板**
  - 在白板上画出10-15个关键界面
  - 按用户流程排列
  - 标注关键交互点

- [ ] **15:30-16:30 细化故事板**
  - 补充界面细节
  - 确定文案和内容
  - 标注技术可行性

- [ ] **16:30-17:00 准备原型清单**
  - 列出需要制作的所有界面
  - 标注优先级
  - 分配制作任务

**产出物清单**:
- [ ] 选定方案
- [ ] 完整故事板（10-15屏）
- [ ] 原型制作清单

---

## Day 4: 原型（Prototype）

**核心目标**: 制作可测试的高保真原型

### 上午（3小时）

- [ ] **09:00-09:30 工具准备**
  - 确定原型工具（Figma/Pencil/其他）
  - 建立组件库

- [ ] **09:30-12:00 制作核心流程**
  - 优先制作主流程界面
  - 保持"刚好够用"的精细度
  - 使用真实内容，不用占位符

### 下午（3小时）

- [ ] **14:00-15:30 完善原型**
  - 添加次要界面
  - 完善交互细节
  - 确保流程完整

- [ ] **15:30-16:30 内部测试**
  - 团队内部走查一遍
  - 修复明显问题
  - 确认原型可运行

- [ ] **16:30-17:00 准备测试脚本**
  - 编写测试任务（5个左右）
  - 准备开场白和结束语
  - 准备记录表格

**产出物清单**:
- [ ] 可点击原型
- [ ] 测试脚本
- [ ] 记录表格

---

## Day 5: 验证（Validate）

**核心目标**: 通过真实用户测试验证方案

### 上午（3小时）

- [ ] **09:00-09:30 测试准备**
  - 检查设备、网络
  - 确认测试环境
  - 复习测试脚本

- [ ] **09:30-12:00 用户测试（第1-3人）**
  - 每场测试45分钟
  - 观察者记录问题和反应
  - 每场结束快速总结

### 下午（3小时）

- [ ] **14:00-15:30 用户测试（第4-5人）**
  - 继续测试
  - 关注模式，而非个案

- [ ] **15:30-16:30 整理洞察**
  - 汇总所有观察记录
  - 识别重复出现的问题
  - 按优先级排序

- [ ] **16:30-17:00 总结汇报**
  - 制作测试总结报告
  - 确定下一步行动
  - 庆祝冲刺完成！

**产出物清单**:
- [ ] 测试观察记录（5份）
- [ ] 问题清单（按频率排序）
- [ ] 下一步行动计划

## 冲刺检查清单

### 冲刺前准备
- [ ] 确定冲刺主题和目标
- [ ] 邀请参与者（5-7人）
- [ ] 预订会议室（5天）
- [ ] 准备材料：白板、便签、马克笔
- [ ] 收集现有用户研究和数据

### 冲刺中注意事项
- [ ] 每天准时开始和结束
- [ ] 手机静音，专注参与
- [ ] 决策人必须全程参与
- [ ] 记录所有产出物

### 冲刺后跟进
- [ ] 整理所有文档和原型
- [ ] 制定实施计划
- [ ] 安排后续迭代
