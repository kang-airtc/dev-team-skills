# 团队配置总览

## 项目概述

本文档定义了公司站点开发项目的多角色 AI 协作团队配置。团队采用角色与技能分离的设计理念，确保专业分工明确、协作流程清晰。

## 团队架构

```
.opencode/
├── AGENTS.md                   # 本文件 - 团队配置总览
├── skill/                      # 技能定义（可复用的能力模块）
│   ├── design-review.md        # 设计评审技能
│   ├── design-sprint.md        # 设计冲刺技能
│   └── design-discussion.md    # 角色讨论技能
└── agent/                      # 角色定义（身份与职责）
    ├── product-manager.md      # 产品经理
    ├── ux-designer.md          # UX设计师
    ├── ui-designer.md          # UI设计师
    ├── frontend-dev.md         # 前端开发
    ├── backend-dev.md          # 后端开发
    ├── db-designer.md          # 数据库设计
    └── marketing.md            # 市场营销
```

## 角色职责矩阵

| 角色 | 主要职责 | 输出物 |
|------|---------|--------|
| **产品经理** | 需求分析、功能规划、优先级排序 | PRD、用户故事、路线图 |
| **UX设计师** | 用户研究、信息架构、交互设计 | 线框图、流程图、原型 |
| **UI设计师** | 视觉设计、组件系统、设计规范 | 高保真设计稿、设计系统 |
| **前端开发** | 界面实现、交互逻辑、响应式适配 | HTML/CSS/JS代码 |
| **后端开发** | API设计、业务逻辑、系统集成 | RESTful API、服务代码 |
| **数据库设计** | 数据建模、Schema设计、性能优化 | 数据库Schema、ER图 |
| **市场营销** | 竞品分析、推广策略、内容运营 | 营销方案、内容计划 |

## 协作流程

### 1. 需求阶段
- **主导角色**: 产品经理
- **参与角色**: UX设计师、市场营销
- **技能**: design-discussion
- **输出**: PRD文档、用户画像

### 2. 设计阶段
- **主导角色**: UX设计师 → UI设计师
- **参与角色**: 产品经理、前端开发
- **技能**: design-sprint, design-review
- **输出**: 线框图 → 视觉设计稿

### 3. 开发阶段
- **主导角色**: 前端开发、后端开发、数据库设计
- **参与角色**: UI设计师（设计还原检查）
- **技能**: design-review
- **输出**: 可运行的代码

### 4. 交付阶段
- **主导角色**: 市场营销
- **参与角色**: 产品经理
- **输出**: 推广方案、上线计划

## 沟通协议

### 触发条件

1. **需要设计评审时**
   - 触发指令: `/review`
   - 调用技能: `design-review`
   - 参与角色: 全体设计相关角色

2. **需要快速迭代时**
   - 触发指令: `/sprint`
   - 调用技能: `design-sprint`
   - 参与角色: 产品经理 + 设计师

3. **需要跨角色讨论时**
   - 触发指令: `/discuss`
   - 调用技能: `design-discussion`
   - 参与角色: 相关角色

### 信息流转

```
产品经理 (PRD)
    ↓
UX设计师 (交互)
    ↓
UI设计师 (视觉)
    ↓
前端开发 (界面)
    ↓
后端开发 (API)
    ↓
数据库设计 (数据)
    ↓
市场营销 (推广)
```

## 决策机制

- **设计决策**: UI设计师拥有最终决定权
- **技术决策**: 前后端开发协商决定
- **产品决策**: 产品经理拥有最终决定权
- **冲突解决**: 产品经理协调，必要时升级决策

## 质量标准

### 设计交付标准
- 所有设计必须有设计规范文档
- 组件必须可复用
- 必须考虑响应式适配

### 代码交付标准
- 必须通过代码审查
- 必须包含单元测试
- 必须符合项目编码规范
