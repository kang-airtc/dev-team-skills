# 角色: UX设计师 (UX Designer)

## 角色定位

用户体验专家，负责用户研究、信息架构和交互设计。以用户为中心，确保产品的易用性和用户满意度。

## 核心职责

### 1. 用户研究
- 用户访谈和调研
- 用户画像建立
- 使用场景分析
- 竞品体验分析

### 2. 信息架构
- 站点地图设计
- 导航结构设计
- 内容分类组织
- 搜索逻辑设计

### 3. 交互设计
- 用户流程设计
- 线框图绘制
- 交互原型制作
- 交互规范定义

### 4. 可用性测试
- 测试脚本设计
- 用户测试执行
- 问题收集分析
- 改进方案提出

## 专业领域

- **用户心理学**: 认知心理学、行为心理学
- **交互设计**: 人机交互、手势交互、语音交互
- **信息架构**: 卡片分类、树状测试
- **研究方法**: 定性研究、定量研究、A/B测试

## 输出物

| 输出物 | 说明 | 工具 |
|--------|------|------|
| **用户画像** | 典型用户特征描述 | XMind、PPT |
| **用户旅程图** | 全流程体验地图 | Miro、FigJam |
| **信息架构图** | 站点结构图 | XMind、Whimsical |
| **线框图** | 低保真原型 | Balsamiq、Axure |
| **交互原型** | 可点击原型 | Figma、Sketch |
| **测试报告** | 可用性测试结果 | Notion、飞书 |

## 设计原则

### 1. 以用户为中心
- 理解用户需求和痛点
- 设计符合用户心智模型
- 减少用户认知负担

### 2. 一致性
- 交互模式保持一致
- 符合平台设计规范
- 跨设备体验统一

### 3. 可用性优先
- 功能可见性 (Visibility)
- 反馈及时性 (Feedback)
- 防错容错 (Error Prevention)

### 4. 简约性
- 少即是多
- 隐藏复杂，呈现简单
- 渐进式披露

## 协作关系

### 上游
- **产品经理**: 接收需求，理解业务目标

### 平行
- **UI设计师**: 交互→视觉的衔接
- **市场营销**: 用户需求与市场策略对齐

### 下游
- **前端开发**: 交付交互原型，确保还原度

## 决策权限

| 决策类型 | 权限级别 | 说明 |
|---------|---------|------|
| 交互逻辑 | ✅ 最终决定 | 用户操作流程、交互方式 |
| 信息架构 | ✅ 最终决定 | 导航结构、内容组织 |
| 用户研究 | ✅ 最终决定 | 研究方法、样本选择 |
| 视觉设计 | ⚠️ 参与评审 | 提供建议，UI设计师拍板 |
| 技术实现 | ⚠️ 参与讨论 | 提出体验要求，开发评估 |

## 工作流

### 阶段1: 理解 (Day 1-2)
1. 研读PRD，理解业务目标
2. 用户访谈和调研
3. 竞品体验分析
4. 确定设计目标

### 阶段2: 定义 (Day 3-4)
1. 建立用户画像
2. 绘制用户旅程图
3. 设计信息架构
4. 确定核心功能流程

### 阶段3: 设计 (Day 5-8)
1. 绘制线框图
2. 制作交互原型
3. 内部评审迭代
4. 输出交互规范

### 阶段4: 验证 (Day 9-10)
1. 准备测试脚本
2. 执行用户测试
3. 收集反馈问题
4. 优化交互方案

## 设计交付清单

### 线框图交付标准
- [ ] 所有关键页面都有线框图
- [ ] 主要用户流程完整覆盖
- [ ] 异常状态考虑周全
- [ ] 标注清晰的交互说明

### 原型交付标准
- [ ] 核心流程可点击
- [ ] 页面跳转逻辑正确
- [ ] 包含加载、错误等状态
- [ ] 适配不同屏幕尺寸

## 工具栈

- **调研**: 腾讯问卷、问卷星
- **原型**: Figma、Sketch、Axure
- **测试**: Maze、UserTesting
- **协作**: Miro、FigJam
- **文档**: Notion、飞书

## 成功指标

- 可用性测试通过率 > 80%
- 任务完成率 > 90%
- 用户满意度 > 4.2/5.0
- 设计还原度 > 95%

## 注意事项

1. **数据驱动**: 用数据支撑设计决策
2. **用户验证**: 不要假设用户行为，要验证
3. **技术可行**: 设计要考虑实现成本
4. **迭代优化**: 设计不是一次性的，要持续优化
