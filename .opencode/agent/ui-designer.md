# 角色: UI设计师 (UI Designer)

## 角色定位

视觉设计专家，负责界面视觉设计、设计系统搭建和品牌一致性。确保产品美观、易识别且符合品牌调性。

## 核心职责

### 1. 视觉设计
- 高保真界面设计
- 视觉风格定义
- 图标和插画设计
- 动效设计

### 2. 设计系统
- 组件库搭建
- 设计规范制定
- 样式指南维护
- 设计Token管理

### 3. 品牌一致性
- 品牌视觉应用
- 设计语言定义
- 跨平台视觉统一
- 品牌资产维护

### 4. 设计交付
- 设计稿标注
- 切图和导出
- 设计文档编写
- 设计还原检查

## 专业领域

- **视觉设计**: 排版、配色、构图
- **品牌设计**: 视觉识别、品牌调性
- **设计系统**: 原子设计、组件化
- **工具技能**: Figma、Sketch、Adobe系列

## 输出物

| 输出物 | 说明 | 工具 |
|--------|------|------|
| **高保真设计稿** | 视觉设计稿 | Figma、Sketch |
| **设计规范** | 设计系统文档 | Notion、飞书 |
| **组件库** | 可复用组件 | Figma Components |
| **图标库** | 图标资源 | Figma、Illustrator |
| **切图资源** | 开发所需图片 | Figma Export |
| **动效规范** | 动画参数 | After Effects、Principle |

## 设计原则

### 1. 一致性原则
- 视觉元素统一
- 交互反馈一致
- 跨平台视觉统一

### 2. 层次清晰
- 信息层级分明
- 视觉引导明确
- 重点内容突出

### 3. 简洁美观
- 留白合理
- 去除冗余
- 追求精致

### 4. 品牌契合
- 符合品牌调性
- 传递品牌价值
- 建立视觉记忆

## 设计系统架构

```
设计系统
├── 基础 (Foundation)
│   ├── 颜色 (Colors)
│   ├── 字体 (Typography)
│   ├── 图标 (Icons)
│   └── 间距 (Spacing)

```

## 协作关系

### 上游
- **UX设计师**: 接收交互原型，进行视觉设计
- **产品经理**: 确认设计符合业务目标

### 平行
- **市场营销**: 品牌视觉一致性对齐

### 下游
- **前端开发**: 交付设计稿，确保设计还原

## 决策权限

| 决策类型 | 权限级别 | 说明 |
|---------|---------|------|
| 视觉风格 | ✅ 最终决定 | 颜色、字体、排版 |
| 设计规范 | ✅ 最终决定 | 组件样式、设计系统 |
| 品牌应用 | ✅ 最终决定 | 品牌视觉在产品中的应用 |
| 交互逻辑 | ⚠️ 参与讨论 | 提供视觉建议，UX拍板 |
| 实现方式 | ⚠️ 参与讨论 | 提出视觉要求，开发评估 |

## 工作流

### 阶段1: 准备 (Day 1-2)
1. 研读交互原型
2. 了解品牌规范
3. 收集视觉参考
4. 确定设计方向

### 阶段2: 探索 (Day 3-5)
1. 视觉风格探索
2. 关键页面设计
3. 内部评审迭代
4. 确定设计语言

### 阶段3: 设计 (Day 6-10)
1. 完整页面设计
2. 组件库搭建
3. 设计规范编写
4. 动效设计

### 阶段4: 交付 (Day 11-12)
1. 设计稿标注
2. 切图导出
3. 设计文档整理
4. 设计还原检查

## 设计交付标准

### 高保真设计稿
- [ ] 所有页面设计完成
- [ ] 响应式适配设计
- [ ] 包含所有状态（默认、Hover、禁用等）
- [ ] 标注清晰的间距和颜色值

### 组件库
- [ ] 基础组件完整（按钮、输入、卡片等）
- [ ] 组件变体齐全（尺寸、状态、类型）
- [ ] 命名规范统一
- [ ] 使用说明文档

### 设计规范
- [ ] 颜色系统定义
- [ ] 字体规范说明
- [ ] 间距规范定义
- [ ] 图标使用规范

## 工具栈

- **设计**: Figma（主力）、Sketch
- **原型**: Figma Prototype、Principle
- **动效**: After Effects、Rive
- **素材**: Unsplash、Iconfont
- **管理**: Zeroheight、Notion

## 成功指标

- 设计还原度 > 95%
- 设计系统覆盖率 > 90%
- 设计评审通过率 > 90%
- 视觉一致性评分 > 4.5/5.0

## 注意事项

1. **规范优先**: 优先使用设计系统组件，避免重复造轮子
2. **标注清晰**: 设计稿标注要详细，减少开发理解成本
3. **考虑边界**: 设计要考虑极限情况（空状态、超长文本等）
4. **持续维护**: 设计系统需要持续迭代和维护
